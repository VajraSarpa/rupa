# Fuzz and property testing, October 2026

Rupa v0.1.4, tested 4 November 2026 with Hypothesis on Python 3.13 and
WeasyPrint 70. Tests: `tests/test_fuzz.py`. src/ was not changed; every bug
below is a plain test marked `xfail(strict=True)`, so a fix turns it into an
XPASS failure until the mark is removed.

Rechecked on v0.1.6 (5 November 2026): all 33 xfails still fail as
recorded. The properties don't exercise DOCX output or charts, which came
later.

```bash
uv run pytest tests/test_fuzz.py -q                             # capped, ~10 s
RUPA_FUZZ_EXAMPLES=1000 uv run pytest tests/test_fuzz.py -q     # deep run
uv run pytest -m "not fuzz" -q                                  # skip them
```

## What the properties check

| Property | Inputs | Holds? |
|---|---|---|
| The CLI exits 0/2/3/4/5, prints one stdout line (or one JSON object), one `rupa: error:` line on stderr when it fails | Markdown built from CommonMark/GFM/footnote/HTML fragments plus random text; frontmatter as dumped YAML over every allowed key and random keys, or raw YAML soup (anchors, aliases, tags, merge keys, bad dates); random bytes; random argv | Yes, outside bugs 1–3, 11, 12 |
| No input reaches the network | All of the above plus image sources over `http`, `https`, `ftp`, `//host`, UNC, inside and outside SVG data URIs, with sockets and DNS replaced by a recorder | Yes |
| No image escapes the input's folder | Image paths built from `..`, `%2e%2e`, absolute paths, `file:` in every case, symlinks to outside, hidden files and folders, a PNG named `.dat`; each planted image has its own size so the output names what was read | Yes for images the Markdown names; **no** for images an SVG names (bugs 4, 5) |
| Raw HTML never comes out live | Script, event-handler, iframe, CDATA and `javascript:` payloads in body text, headings, tables, code fences and info strings, link titles, footnotes, task lists, and in title/subtitle/author | Yes: only markdown-it's own tags, no `on*` attributes, no `javascript:`/`vbscript:`/non-image `data:` URLs, one `<style>` |
| `rupa verify` never crashes | A real Rupa PDF truncated, bit-flipped, spliced and cut; hand-built PDFs with random MediaBoxes (zero, negative, inverted, 14400 pt, non-numbers), 0–4 pages of random content operators, every `--sample` mode; empty, zero-page and password-protected PDFs; random wants files | Yes, outside bugs 6–10, 13–15 |

## Bugs

Severity: **high** breaks the security contract; **medium** is a crash (exit
1) or wrong exit code on plausible input; **low** is a contract nit.

### 1. Ints over 4,300 digits crash the render (medium)

- **Input:** frontmatter `title: 0xFFF…` (4,000 hex digits). Same for
  `subtitle`, `author`, `date`, and for `theme` and `toc`, which crash while
  building the error message. `pages: 0xFFF…` renders, then crashes with
  `--json`.
- **What happened:** `ValueError: Exceeds the limit (4300 digits) for
  integer string conversion`, traceback, exit 1. YAML parses hex, octal and
  binary ints without Python's digit limit; `str()`, `repr()` and
  `json.dumps` then hit it.
- **Contract:** bad input is exit 3; a crash is never expected.
- **Fix:** in `_check_meta`, reject ints whose `bit_length()` exceeds, say,
  64 before any `str`/`repr` (`src/rupa/document.py:71`, `:75`, `:78`,
  `:82`; `pages` at `:84`). That also covers `src/rupa/cli.py:144`.
- **Tests:** `test_bug01_*`.

### 2. A YAML `\uD800` escape crashes HTML output (medium)

- **Input:** `title: "\uD800"`, `-o out.html`.
- **What happened:** PyYAML turns the escape into a lone surrogate;
  `.encode("utf-8")` at `src/rupa/cli.py:123` raises `UnicodeEncodeError`,
  exit 1. PDF output fails with exit 4 (`PDF render failed`) instead.
- **Contract:** bad input is exit 3, one line.
- **Fix:** in `_check_meta` (`src/rupa/document.py:75`), raise `InputError`
  when a text field doesn't encode as UTF-8 (`value.encode("utf-8")` in a
  try). `theme` too.
- **Test:** `test_bug02_surrogate_in_frontmatter_crashes_html`.

### 3. `%00` in an image path crashes (medium)

- **Input:** `![x](a%00.png)`, HTML or PDF.
- **What happened:** `unquote` yields a NUL; `Path.resolve()` at
  `src/rupa/render.py:223` raises `ValueError: embedded null character`,
  exit 1.
- **Contract:** a refused image fails the render, exit 4 (or 3 if refused
  at parse time).
- **Fix:** in `load_image`, refuse a decoded path containing `"\x00"` with
  `RenderError` before resolving (`src/rupa/render.py:223`), or reject it in
  `_check_image` (`src/rupa/document.py:162`).
- **Test:** `test_bug03_nul_in_image_path_crashes`.

### 4. An SVG's `<image href="FILE://…">` reads any file on disk (high)

- **Input:** `![x](data:image/svg+xml;base64,…)` where the SVG holds
  `<image href="FILE:///home/me/photo.png"/>`, rendered to PDF.
- **What happened:** exit 0, and the outside image is embedded in the PDF.
  `load_image` checks the SVG parses but not what it references; WeasyPrint
  then fetches the SVG's own `<image>` through `ContainedFetcher`, whose
  check is `url.startswith("file:")` (`src/rupa/render.py:306`). `FILE:`
  skips the check, and WeasyPrint's base `URLFetcher` lowercases the scheme
  and opens the file. Any readable PNG/JPEG/GIF/WebP/SVG on the machine can
  be pulled into the PDF, so Markdown from an untrusted source (a pasted
  document, a prompt-injected page) can exfiltrate images the user never
  named. Lowercase `file:` outside the folder is blocked (the image is
  silently dropped).
- **Contract:** "only files inside that folder"; the fetcher allows "files
  under base, Rupa's own fonts, and data: URIs only".
- **Fix:** since every image reaches WeasyPrint already inlined, the fetcher
  needs no document files at all. Allow only `data:` and fonts:
  `scheme = url.split(":", 1)[0].lower()`; if `scheme == "file"`, require
  `path.parent == FONT_DIR`, else refuse (`src/rupa/render.py:305-310`).
  Optionally also strip or refuse `<image>`, `<use>`, `<feImage>` and
  `xlink:href` with non-`data:` targets in `_decoded_mime`'s SVG branch
  (`src/rupa/render.py:164-173`), so HTML output carries no such references
  either.
- **Test:** `test_bug04_svg_image_with_uppercase_file_url_escapes_the_folder`.

### 5. An SVG's `<image>` reads hidden and non-image files inside the folder (high)

- **Input:** an SVG data URI with `<image href="file:///…/doc/.private/x.png"/>`
  or `…/doc/secret.dat` (PNG bytes, wrong extension).
- **What happened:** exit 0, image embedded. The fetcher only checks "inside
  base", not the hidden-part or extension rules `load_image` applies.
- **Contract:** "never hidden ones, with an image extension".
- **Fix:** the same as bug 4: the fetcher should refuse every `file:` URL
  but the fonts (`src/rupa/render.py:308`).
- **Test:** `test_bug05_svg_image_reads_hidden_or_non_image_files`.

### 6. A non-UTF-8 wants file crashes verify (medium)

- **Input:** `rupa verify x.pdf --wants w.yaml`, `w.yaml` in Latin-1.
- **What happened:** `UnicodeDecodeError` from `read_text`, exit 1.
- **Contract:** exit 3, one line.
- **Fix:** catch `UnicodeDecodeError` next to `OSError` in `load_wants`
  (`src/rupa/verify.py:86-88`).
- **Test:** `test_bug06_non_utf8_wants_crashes`.

### 7. A deeply nested wants file crashes verify (medium)

- **Input:** `rubric: [[[[…]]]]`, 5,000 deep.
- **What happened:** `RecursionError`, exit 1. `document.parse` catches this
  for frontmatter; `load_wants` doesn't.
- **Fix:** catch `RecursionError` in `load_wants` (`src/rupa/verify.py:89`).
- **Test:** `test_bug07_deeply_nested_wants_crashes`.

### 8. An impossible date in a wants file crashes verify (medium)

- **Input:** `theme: 2026-02-30`.
- **What happened:** PyYAML's timestamp constructor raises `ValueError`, exit 1.
- **Fix:** catch `ValueError` and `OverflowError` too, as `document.parse`
  does (`src/rupa/verify.py:89`). Bugs 6–8 are one `except` clause.
- **Test:** `test_bug08_impossible_date_in_wants_crashes`.

### 9. Ints over 4,300 digits in a wants file crash verify (medium)

- **Input:** `max_pages: 0xFFF…` (valid, passes validation) or
  `text_color: 0xFFF…` (invalid).
- **What happened:** exit 1. `max_pages` crashes in the eagerly built detail
  string `f"{last} pages > max {wants['max_pages']}"`
  (`src/rupa/verify.py:382`); `text_color` in `{color!r}`
  (`src/rupa/verify.py:140`).
- **Fix:** cap `max_pages` in `_validate` (`src/rupa/verify.py:134`, e.g.
  `<= 100_000`) and quote values through `clip(repr(…))` guarded the same way
  as bug 1.
- **Test:** `test_bug09_huge_int_in_wants_crashes`.

### 10. Wants errors quote values unclipped (low)

- **Input:** `text_color: 'xxx…'` (500 chars) or `checks: ['xxx…']`.
- **What happened:** the whole value is echoed into the one-line error.
- **Contract:** "quoted values are clipped at 80 characters (`document.clip`)".
- **Fix:** wrap in `clip()` at `src/rupa/verify.py:140` and `:148`.
- **Test:** `test_bug10_wants_errors_quote_values_unclipped`.

### 11. A newline in a path splits the status line (low)

- **Input:** `rupa -o $'a\nb.html'`; or `rupa verify $'a\nb.pdf'` with sheets.
- **What happened:** exit 0, two stdout lines. `_err` collapses whitespace,
  but the success lines print the path raw.
- **Contract:** stdout is exactly one status line.
- **Fix:** print paths escaped, e.g. a helper that replaces control
  characters with `\n`-style escapes, at `src/rupa/cli.py:149` and
  `src/rupa/verify.py:625`. (`--json` is already safe.)
- **Tests:** `test_bug11_*`.

### 12. Usage errors are four lines, and ignore `--json` (low)

- **Input:** `rupa` with no `-o`, `--pages abc`, an unknown flag,
  `rupa verify` with no PDF.
- **What happened:** exit 2 (correct), but argparse prints a three-line
  usage block before `rupa: error: …`, and with `--json` stdout is empty.
- **Contract:** "Errors are one line on stderr"; one JSON object with `--json`.
- **Fix:** subclass `ArgumentParser` and override `error()` to call `_err`
  with the message and `sys.exit(EXIT_USAGE)`; detect `--json` in `argv`
  before parsing. Applies to `src/rupa/cli.py:49`, `:171` and `:226`. Keep
  `--help` as is.
- **Tests:** `test_bug12_*`.

### 13. pdfminer warnings add lines to stderr (low)

- **Input:** a PDF with a malformed MediaBox (`[0 0 1e9 1e9]`), or a font
  without a FontBBox.
- **What happened:** pdfminer logs `Invalid MediaBox in /Page, defaulting to
  US Letter` or `Could not get FontBBox…`; with no handler configured,
  Python's `logging.lastResort` prints it to stderr. On a failure that's
  two stderr lines; on success, a stray line.
- **Fix:** in `main` (`src/rupa/cli.py:337`), or before opening PDFs in
  `verify.py:254`, `logging.getLogger("pdfminer").addHandler(logging.NullHandler())`
  and the same for `pdfplumber`.
- **Test:** `test_bug13_pdfminer_warnings_add_stderr_lines` (subprocess,
  because pytest's log capture hides the warning in-process).

### 14. Pattern-filled text makes a valid PDF "unreadable" (low)

- **Input:** a valid PDF whose text uses `/Pattern cs /P0 scn` (pdfium reads
  it fine).
- **What happened:** exit 3, `cannot read PDF …: unsupported operand
  type(s) for -: 'str' and 'float'`. pdfplumber reports the colour as the
  pattern name; `_to_rgb` (`src/rupa/verify.py:226-238`) passes a 1-tuple of
  a `str` through as grey and `_same_color` (`:242`) subtracts it.
- **Contract:** verify should report `text-color` failing (exit 5), not
  call the file unreadable.
- **Fix:** in `_to_rgb`, return `None` unless every component is a number;
  `None` already counts as off-colour.
- **Test:** `test_bug14_pattern_filled_text_is_not_an_unreadable_pdf`.

### 15. A password-protected PDF's error doesn't say why (low)

- **Input:** an RC4-encrypted PDF with a user password.
- **What happened:** exit 3 (correct), message `cannot read PDF x.pdf: `,
  because `PDFPasswordIncorrect` has an empty message.
- **Fix:** at `src/rupa/verify.py:260`, use `str(exc) or
  type(exc).__name__`, or catch the password error and say "is
  password-protected".
- **Test:** `test_bug15_password_pdf_error_says_why`.

### 16. Upper-case `DATA:` or `;BASE64` data URIs are refused (low)

- **Input:** `![x](DATA:image/png;base64,…)` or `data:image/png;BASE64,…`.
- **What happened:** exit 4. `_check_image` accepts the URI
  case-insensitively, but `load_image` checks `src.startswith("data:")` and
  `header.endswith(";base64")` case-sensitively, so the first is treated as
  a file path and the second as percent-encoded bytes.
- **Contract:** URI schemes and the `base64` token are case-insensitive
  (RFC 3986, RFC 2397); Rupa says it accepts `data:image` URIs.
- **Fix:** compare lowercased at `src/rupa/render.py:209` and `:213`.
- **Test:** `test_bug16_uppercase_data_uri_is_refused`.

### 17. A UTF-8 BOM hides the frontmatter (low)

- **Input:** a file saved with a BOM (common on Windows) starting `---`.
- **What happened:** exit 0, but the frontmatter isn't recognised: it
  renders as a rule and a `title: …` heading, and the title is lost.
- **Fix:** decode with `"utf-8-sig"` at `src/rupa/cli.py:108`.
- **Test:** `test_bug17_bom_hides_frontmatter`.

### 18. An empty image source vanishes (low)

- **Input:** `![alt text](<>)`.
- **What happened:** exit 0. `_IMG_SRC` (`src/rupa/render.py:147`) needs at
  least one character, so `load_image` never sees the image; the PDF shows
  the alt text and the HTML keeps `<img src="">`.
- **Contract:** "a missing, refused or undecodable file fails the render
  (exit 4) rather than vanishing"; "WeasyPrint never swaps a bad image for
  its alt text".
- **Fix:** refuse an empty `src` in `_check_image`
  (`src/rupa/document.py:162`), exit 3.
- **Test:** `test_bug18_empty_image_src_vanishes`.

## What held

- **Raw HTML.** Nothing in the body, headings, tables, code fences (including
  hostile info strings), link titles, footnotes, task lists or the
  title/subtitle/author came out as a live tag or attribute. `javascript:`
  and `vbscript:` links stay text; non-image `data:` links are refused.
- **Network.** No input opened a socket or resolved a name. Remote images
  are refused at parse time (exit 3); remote references inside SVGs are
  refused by the fetcher's protocol list.
- **Folder containment for named images.** `..`, encoded `..`, absolute
  paths, `file:` URLs in any case, symlinks out of the folder, hidden files
  and folders, and wrong extensions all fail with exit 3 or 4. Only the SVG
  path (bugs 4 and 5) gets round it.
- **Frontmatter.** Aliases (exit 3, no expansion), `!!python/object` tags,
  unhashable keys, merge keys, deep nesting, impossible dates and wrong
  types are all one-line exit-3 errors.
- **verify on bad PDFs.** Empty, non-PDF, header-only, truncated at every
  cut, bit-flipped, zero-page, zero-size, password-protected (exit 3) and
  no-user-password encrypted PDFs (read normally). 14400 pt and inverted
  pages verify, with sheets capped at 3,300 px. Mutated real PDFs and
  random content streams never crashed.
- **Arbitrary bytes and argv.** Invalid UTF-8 is exit 3; abbreviations and
  bad flag values are exit 2; nothing crashed.

## Notes

- `rupa verify --json` prints the indented `verify.json` (one object over
  several lines), while `rupa --json` prints one line. Both match "one JSON
  object", so this isn't listed as a bug, but a one-line verify object would
  be easier for wrappers.
- A deep run (600 examples per property) found nothing beyond bugs 1–18.

## Not covered

- `rupa refs` (a maintainer command that writes into `src/`).
- The plugin and its hook.
- Resource limits: a huge but valid document or image is slow, not wrong;
  no property bounds time or memory.
