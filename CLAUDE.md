# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Rupa is a CLI that renders Markdown (plus optional YAML frontmatter) into a
themed HTML page or PDF, checks the PDF, and ships a Claude Code plugin whose
skill makes Claude use it instead of hand-writing markup.

## Commands

```bash
uv sync                                   # needs Pango for WeasyPrint (see README)
uv run pytest -q                          # 80 tests
uv run pytest tests/test_verify.py::test_stranded_heading_fails   # one test
uvx ruff check src tests                  # CI runs this too
echo "# Hello" | uv run rupa -o out/hello.pdf && uv run rupa verify out/hello.pdf
uv run rupa refs                          # after any theme CSS change; commit the PNGs
uv run python docs/build.py               # re-render docs/dist/ with Rupa itself
claude plugin validate ./plugin           # after any edit to plugin/
```

`claude plugin validate` needs a recent Claude Code CLI; older ones reject the
`displayName` key in `plugin.json`.

**Ask before running anything that spends tokens:** `claude plugin eval` (see
`plugin/evals/README.md`; start with `--tag trigger --runs 1`) and
`bench/bench.sh` (calls `claude -p` for real; `bench/fake/claude` exists for
testing the script without spending).

## Architecture

The pipeline is `document.py` → `render.py` → (PDF) → `verify.py`, wired by
`cli.py`.

- **`document.py`** parses Markdown into a `Document` (meta, body HTML,
  headings). This is the contract boundary: Claude supplies content only.
  Frontmatter keys are restricted to `ALLOWED_META` (title, subtitle, author,
  date, theme, toc); anything else is an `InputError`. Raw HTML is escaped
  (`html=False`), never passed through.
- **`render.py`** owns all styling: a Jinja template plus `themes/<name>.css`,
  with `themes/print.css` appended for PDF. Themes must be listed in
  `THEMES`.
- **Images:** `document.py` rejects any image that isn't a relative path or a
  `data:image` URI (exit 3), so neither HTML nor PDF ever fetches from the
  network. For PDF, relative paths resolve against the input file's folder
  (cwd for stdin), and the WeasyPrint fetcher refuses files outside it; a
  missing or refused file fails the render (exit 4) rather than vanishing.
- **`verify.py`** reads the PDF with pdfplumber into `PageInfo`/`Line`
  records, classifies pages (cover / prose / table / code), runs the checks
  in `ALL_CHECKS` against a wants dict (`DEFAULT_WANTS`, overridable by a
  `wants.yaml`; `wants.example.yaml` documents every key), then writes
  side-by-side sheets (reference page | rendered page) and `verify.json` to
  `<pdf>.verify/`. Rupa never calls a model; the plugin skill has Claude judge
  the sheets against the rubric.
- **Reference pages** live in `src/rupa/references/<theme>/{cover,prose,table,code}.png`,
  generated by `rupa refs` from `references/sample.md`. A new theme needs its
  CSS, a `THEMES` entry, and a `rupa refs --theme <name>` run.

### CLI contract (don't break it; the plugin and evals depend on it)

- stdout is exactly one status line (or one JSON object with `--json`),
  never the document.
- Exit codes: `0` ok, `2` usage, `3` bad input, `4` render failure,
  `5` verify checks failed, or a PDF still over its `pages` budget.
- Status-line wording is matched by evals (e.g. `verify: N/N checks pass`).

### Plugin (`plugin/`)

One skill, `skills/render/SKILL.md` (`rupa:render`), plus a SessionStart hook
that warns if `rupa` isn't on PATH. The skill's rules: write Markdown, never
hand-write HTML/CSS/PDF code, fix verify failures in the Markdown only (at most
two rounds), and report theme problems instead of editing CSS. The skill's
`description` drives triggering; the `trigger` eval cases test it.
`bench/bench.sh` builds its render-only arm by cutting SKILL.md from
`## Verify` to `Do not add styling`, and its per-type arm by rewriting the
`` `rupa verify out/report.pdf` `` example, so keep those intact.

## Conventions

- A different look is a theme change, never styling added to Markdown.
- PDF text is forced to solid black (`text-color` check); keep it that way in
  themes.
- PDFs use the bundled fonts in `src/rupa/themes/fonts/`, never system fonts,
  so renders, reference pages and fit constants match on every machine. The
  image guard in `render.py` allows that folder and nothing else outside the
  document's own. Use weights 400/500/600/700 only; WeasyPrint drops others.
- `docs/build.py` expands `@@include path lang@@` lines with real source
  files, so the guide quotes code directly from `src/`.
